# Auth module — current state

Migrated out of the root `CLAUDE.md` (2026-08-15) so this detail only loads when you're actually working under `src/features/auth/` or `functions/src/auth/`. Same "facts, not standards" rule applies — if your change alters a fact here, update it in the same commit.

- **Self-service registration is shipped, against what `AUTHENTICATION.md` §5 says (2026-08-14).** The doc specifies HR-provisioned accounts and "users are **not** self-registered", but that provisioning flow has no UI or callable, so only the bootstrap superAdmin could ever sign in. `/register` ([src/features/auth/RegisterPage.tsx](src/features/auth/RegisterPage.tsx), public route) collects Full Name → Outlet → Department → Role, each dropdown narrowed by the one above it, and `registerUser` ([functions/src/auth/registerUser.ts](functions/src/auth/registerUser.ts)) writes `users/{uid}` with `status: 'active'`. `ProtectedRoute` now splits the two denial cases: **no profile → `/register`**, profile present but not active → `/unauthorized`. Notes: the org chart lives in `src/constants/organization.ts` mirrored by `functions/src/lib/organization.ts` (constants, not `outlets`/`departments` Firestore docs — nothing edits them and there is no Settings UI); `OUTLET_DEPARTMENTS` is *derived* from outlet concept type since no doc maps outlets to departments; `superAdmin` is absent from every `DEPARTMENT_ROLES` list so it can't be self-granted; and `registerUser` seeds `roles/{roleId}` from `ROLE_PERMISSIONS` (RBAC.md §4/§5) the first time a role is claimed, since only `roles/superAdmin` was ever created by hand.
